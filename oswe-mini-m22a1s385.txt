## 📋 Vulnerabilities (file & line numbers)
(Exact line numbers point to the original insecure input_backup.py entries.)

1) Hardcoded secrets (Critical) — input_backup.py lines [11,12,13]  
   - Issue: `PAYMENT_TOKEN`, `MAIL_SERVER_KEY`, `INTERNAL_AUTH` in source.  
   - Fix: Move to environment variables and fail if missing.  
   - Snippet: `PAYMENT_TOKEN = os.environ.get("PAYMENT_TOKEN")`

2) Weak hashing MD5 (High) — input_backup.py lines [18-21]  
   - Issue: `hashlib.md5` used to generate tokens.  
   - Fix: Use HMAC-SHA256 with a server-only secret: `hmac.new(INTERNAL_AUTH.encode(), username.encode(), hashlib.sha256).hexdigest()`

3) SQL Injection (Critical) — input_backup.py lines [24-31] (vulnerable query on line 27)  
   - Issue: user input interpolated into SQL string.  
   - Fix: Use parameterized queries with `?` placeholder and validate `uid` as integer.  
   - Snippet: `c.execute("SELECT id, name, balance FROM profiles WHERE id = ?", (int(uid),))`

4) Command Injection / Shell Execution (Critical) — input_backup.py lines [50-52]  
   - Issue: `subprocess.Popen(cmd, shell=True)` with user-supplied `name`.  
   - Fix: Use Python `zipfile` and validate `name` pattern.  
   - Snippet: `with zipfile.ZipFile(archive_name, "w") as zf: zf.write(DB_FILE)`

5) SSRF / Unvalidated URL (High) — input_backup.py lines [34,40]  
   - Issue: `requests.post(url, ...)` uses user-supplied URL without validation or timeout.  
   - Fix: Require `https` scheme, optionally restrict to ALLOWED_NOTIFY_HOSTS via env var, use `timeout=5`.  
   - Snippet: parsed = urlparse(url); check scheme and hostname

6) Arbitrary File Read (Medium) — input_backup.py lines [44-46]  
   - Issue: `update_records` opens user-specified path — path traversal risk.  
   - Fix: Restrict to a `configs/` directory and normalize path before opening.  

7) Debug Mode Enabled (Low) — input_backup.py lines [87-88]  
   - Issue: `app.run(debug=True)` in code.
