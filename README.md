# Security Audit & Test Suite

## Overview ✅
This workspace contains a security-audited and fixed version of `inputs.py`, plus automated tests and environment scripts to reproduce and verify the fixes.

Files generated:
- `input_backup.py` — original source backup (vulnerable)
- `inputs.py` — hardened, secure version
- `report.json` — structured vulnerability report with fixes
- `test_runner.py` — small static analyzer used by test scripts
- `run_test.sh` / `run_test.bat` — test harness scripts (Linux/macOS and Windows)
- `auto_test.py` — automatic test execution & logging
- `requirements.txt` — Python dependencies
- `Dockerfile` — container setup for running the tests
- `setup.sh` — quick environment setup for Linux/macOS
- `logs/test_run.log` — test run logs (generated by `auto_test.py`)


## Setup (Linux / macOS) 🛠️
1. Create a virtual environment and install dependencies:
   - `bash setup.sh`
2. Set required environment variables (replace values):
   - `export INTERNAL_AUTH="<strong-secret>"`
   - `export ADMIN_API_KEY="<admin-key>"`
   - (Optional) `export PAYMENT_TOKEN=...`, `MAIL_SERVER_KEY=...`, `DB_FILE=...`, `CONFIG_DIR=...`

## Setup (Windows)
1. Create a virtual environment and install dependencies manually:
   - `python -m venv .venv`
   - `.\.venv\Scripts\activate`
   - `pip install -r requirements.txt`
2. Set environment variables in PowerShell:
   - `$env:INTERNAL_AUTH = '<strong-secret>'`
   - `$env:ADMIN_API_KEY = '<admin-key>'`


## Running tests
- On Linux/macOS:
  - `./run_test.sh input_backup.py vulnerable`  # verifies original file is vulnerable
  - `./run_test.sh inputs.py secure`           # verifies patched file is secure
- On Windows (PowerShell):
  - `run_test.bat input_backup.py vulnerable`
  - `run_test.bat inputs.py secure`


## Automatic testing with `auto_test.py` ⚙️
- `python auto_test.py` — auto-detects the platform and runs both tests (backup and patched) in sequence.
- Logs are appended to `logs/test_run.log` with timestamps and final status lines `TEST PASSED` or `TEST FAILED`.


## Interpreting test results 📋
- Tests for `input_backup.py` should confirm that vulnerability signatures exist.
- Tests for `inputs.py` should confirm signature absence and presence of secure indicators like `hmac.new`, `require_api_key`, and `zipfile.ZipFile`.
- `auto_test.py` writes a final `TEST PASSED` if both tests return success; otherwise `TEST FAILED`.


## Notes & Next Steps 💡
- Secrets must be provided via secure secret stores in deployment (e.g., environment variables injected by secrets manager).
- Consider adding runtime unit tests and integration tests exercising endpoints using proper test fixtures.
- For production deployments, configure TLS, proper logging sinks, monitoring and rotating secrets regularly.
